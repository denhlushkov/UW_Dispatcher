# Стандарт: Definition of Done

Зміна (PR) вважається завершеною, коли виконано **всі** застосовні пункти. Пункти з позначкою 🤖
перевіряє машина (hook + CI) — їх неможливо «забути». Решту автор відмічає в чеклісті PR
([шаблон](../.github/pull_request_template.md)), рев'юер перевіряє.

## 1. Код

- [ ] 🤖 `npm run verify` зелений локально і в CI (повний перелік — [checks.md](checks.md)).
- [ ] 🤖 Межі модулів дотримані (`deps:check`); якщо межа змінилася — оновлено spec §3 і є ADR.
- [ ] Код у правильному шарі: маршрут знає лише HTTP, сервіс — бізнес-операції й доступ,
      SQL і транзакції — лише в репозиторії ([code-style.md](code-style.md#шари)).
- [ ] Немає `TODO` без посилання на issue; немає закоментованого коду.
- [ ] Нові залежності (npm) обґрунтовані в описі PR; архітектурні — мають ADR.

## 2. Тести

- [ ] 🤖 Усі тести проходять; smoke-тест зібраного артефакту проходить.
- [ ] Нова доменна логіка (`domain/`) покрита unit-тестами **за гілками**, а не лише рядками:
      кожен рядок таблиці переходів / кожна гілка умови має тест.
- [ ] Новий сценарій SC-nn має інтеграційний або E2E-тест (з Лаб 3 — обов'язково).
- [ ] Виправлений баг має регресійний тест, який падає без виправлення.

## 3. Документація

- [ ] Поведінка, дані або межі змінилися → оновлено `spec.md` (у тому ж PR).
- [ ] Виконано критерії ADR ([adr-format.md](adr-format.md#коли-adr-обовязковий)) → є ADR.
- [ ] Змінилися команди / змінні оточення → оновлено `README.md` і `.env.example`.
- [ ] 🤖 `docs:check` зелений (формат spec і ADR).

## 4. Експлуатаційна готовність

- [ ] Логи — лише через `platform/logger`, структуровані, з `bpId`; без секретів (🤖 `no-console`,
      `logger-impl-only-in-platform`).
- [ ] Помилки доходять до глобального обробника; немає `try/catch`, що ковтає помилку без дії.
- [ ] Зовнішні виклики мають таймаут; повтори — лише для ідемпотентних операцій.
- [ ] Конфігурація — через `platform/env` зі схемою (невалідне оточення валить старт).

## 5. Процес

- [ ] 🤖 Коміти у форматі Conventional Commits (commitlint).
- [ ] Зміна в feature-гілці, PR у `main`, опис PR: що/навіщо, ID сценаріїв і вимог, як перевірити.
- [ ] Hook-и не обходились (`--no-verify` заборонено).

## Що **не** є Done

- «Працює на моїй машині», але CI червоний.
- Код є, але spec описує стару поведінку.
- Тест, що виконує код, але нічого не перевіряє (без `expect` на результат) — з Лаб 3 таке
  виявляє мутаційне тестування.

## DoD лабораторної роботи

Додатково до DoD кожного PR: `defense/labN/DEFENSE.md` заповнений (що зроблено, як перевірити
однією командою, рішення з посиланнями на ADR, аудит), PR змерджений у `main`.
