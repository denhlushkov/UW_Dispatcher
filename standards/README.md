# Інженерні стандарти UW Dispatcher

Стандарти діють на весь курс. Кожен стандарт складається з трьох частин:

1. **Правило** — що саме вимагається.
2. **Обґрунтування** — яку конкретну проблему правило запобігає (без нього правило не приймається).
3. **Механізм** — як порушення виявляється: автоматично (hook / CI) або через чекліст DoD у PR.

Правило без механізму — побажання. Тому все, що можна перевірити машиною, перевіряє машина;
решта — пункти [Definition of Done](definition-of-done.md), які автор явно відмічає в PR.

| Стандарт                                       | Про що                                                               | Механізм                                         |
| ---------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------ |
| [spec-format.md](spec-format.md)               | Структура `spec.md`: розділи, ID вимог і сценаріїв, шаблон сценарію. | `npm run docs:check` (pre-commit, CI)            |
| [adr-format.md](adr-format.md)                 | ADR у форматі MADR 4: коли писати, статуси, обов'язкові розділи.     | `npm run docs:check` (pre-commit, CI)            |
| [adr-template.md](adr-template.md)             | Шаблон нового ADR.                                                   | —                                                |
| [definition-of-done.md](definition-of-done.md) | Коли зміна вважається завершеною.                                    | Чекліст у PR-шаблоні + автоматичні перевірки     |
| [checks.md](checks.md)                         | Перелік автоматичних перевірок, де і коли вони запускаються.         | husky hooks + GitHub Actions                     |
| [code-style.md](code-style.md)                 | Мова, іменування, шари, помилки, логування, коміти, гілки.           | ESLint, Prettier, dependency-cruiser, commitlint |

## Як змінювати стандарти

Стандарт змінюється так само, як код: окремий PR зі scope `docs`, з обґрунтуванням у описі.
Якщо зміна послаблює перевірку (наприклад, вимикає правило ESLint чи межу модулів), потрібен ADR.
Обхід hook-ів (`git commit --no-verify`) заборонений — CI запускає ті самі перевірки й не дасть
змерджити PR.
